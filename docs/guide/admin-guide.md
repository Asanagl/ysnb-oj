# YSNB OJ 管理员 / 出题人手册

> 读者对象：管理员（admin / super_admin）与出题人（setter）。
>
> 管理入口是独立的 `/admin` 控制台（自带侧边栏布局，992px 以下折叠为纯图标）。
> **setter 只能看到与自己工作相关的四个页面**：题目审核、题目管理、比赛管理、
> 插件系统；数据总览、用户管理、判题机监控、日志查看器、API 密钥仅 admin 及
> 以上可见（菜单按角色自动裁剪，越权访问会被路由守卫拦下）。
>
> 相关文档：选手侧操作见 `user-guide.md`；SPJ/交互题调用约定见
> `interactive.md`；部署与服务器运维见 `../operations/deploy.md`、
> `../operations/maintenance.md`；接口细节见 `../reference/api.md`。

## 一、权限速查

| 能力 | user | setter | admin | super_admin |
|---|:-:|:-:|:-:|:-:|
| 刷题、参赛、用户出题（走审核）、导入外站题目（走审核） | ✓ | ✓ | ✓ | ✓ |
| 题库直接出题、题目包导入/导出、题单 | | ✓ | ✓ | ✓ |
| 创建/管理比赛、赛中裁判（自己创建的比赛） | | ✓ | ✓ | ✓ |
| 题目审核（通过/驳回）、插件清单查看 | | ✓ | ✓ | ✓ |
| 数据总览、判题机监控、日志查看器 | | | ✓ | ✓ |
| 用户管理：封禁 user/setter、重置密码、邀请码、CSV 导入、改角色 user↔setter | | | ✓ | ✓ |
| API 密钥、webhook 目标管理 | | | ✓ | ✓ |
| 授予/收回 admin 与 super_admin、封禁 admin | | | | ✓ |

权限边界（服务端强制，界面只是跟着做）：

- 任何人都不能修改自己的角色；系统任意时刻**恰好有一名 super_admin**——授予他人
  super_admin 时旧 super_admin 自动降为 admin（自动继任：新任就任、旧任卸任），
  收回最后一名会被拒绝。新装系统的首建管理员固定为 uid 0 的 super_admin。
- admin 只能在 user↔setter 之间改角色，且只能封禁 user/setter；授予/收回
  admin、封禁 admin 是 super_admin 专属操作。
- 封禁即时生效：被封用户的下一次请求就会被拒绝，无法登录、无法提交。

## 二、我要出一道题

**前置条件**：账号角色为 setter 及以上。

**逐步操作**：

1. 后台「题目管理」→「新建题目」，进入全页编辑器（`/problems/new`，左侧
   编辑、右侧实时预览）。编辑已有题目走列表的「编辑」（`/problems/:id/edit`）。
2. 填写内容：标题、题面（所见即所得编辑器，支持代码块/图片/链接，右侧实时
   预览）、输入描述、输出描述、提示（可选）、标签、来源；样例用「+ 添加样例」
   逐对填写输入/输出。
3. 设置参数：时限 ms、内存 MB、可见性（隐藏（仅出题人）/ 仅注册用户 / 公开）、
   判题模式（标准比对 / SPJ 特判 / 交互题）。
4. 点「保存」。**先保存才能传测试数据**（保存后页面出现「测试数据」区）。
5. 上传测试数据（见下），需要时在编辑器里「复制题目」「导出 zip」。

**测试数据**：

- 整包 zip：按 `1.in/1.out`、`2.in/2.out`…… 命名，「整包 zip 替换」一次到位
  （替换全部旧测试点）；也可「追加单个测试点」逐个传 `.in`（必选）+ `.out`。
- 测试点列表可逐个预览 in/out、删除单点。
- 交互题允许没有 `.out`（interactor 自行判断正确性）。

**验证**：自己提交一份正确解（应 AC）和一份故意错误解（应 WA），确认数据
强度与时限合理；样例必须与题面一致。

**举例**：A+B 题——时限 1000 ms、内存 256 MB、可见性「仅注册用户」、判题模式
「标准比对」、2 组样例、10 个测试点 zip。

### SPJ 特判题（判题模式 = SPJ 特判）

- checker 是单个 C++17 源文件（testlib 风格），直接粘贴进文本框，或选 `.cpp`
  文件「上传并保存」。
- 调用约定：`./checker <input> <answer> <output>`。
- 退出码：`0` = AC；**任何非零退出码 = WA**，stderr 第一行作为反馈展示给
  选手（stderr 为空时显示 `checker exit N`）。
- 判题机按源码 sha256 缓存编译产物，改源码后自动重编译，无需手动干预。

### 交互题（判题模式 = 交互题）

- interactor 是单个 C++17 源文件：`./interactor <input>`，其 stdin/stdout 与
  选手程序的 stdout/stdin 通过管道直连，双方都跑在沙箱里（interactor 同样
  禁网、限资源）。
- 退出码：`0` = 通过（若选手程序自身 TLE/RE，按选手侧状态判）；`1` = WA
  （stderr 第一行作为反馈）；**其他退出码（含 `2`）= SE**，属判题侧故障，
  用日志查看器排查（见第十一节）。
- 防死锁：任一进程退出即终止另一方；interactor 固定 30s 看门狗。

### IOI 分值表（按测试点配分）

- 仅对 IOI 赛制比赛生效（ACM 赛制忽略），需先把测试数据传完。
- 暂无网页表单，用 API 配置（setter 及以上）：
  `PUT /api/v1/problems/:id/case-scores`，body 形如
  `{"scores": {"1": 20, "2": 30, "3": 50}}`；`GET` 同路径查看当前配分与合计。
- 服务端校验：测试点编号必须已存在、总分必须为正。约定每题合计凑成
  **100 分**，IOI 榜单按总分排名，读起来最直观。

## 三、我要导入一套题目包（自有 / DOMjudge / Hydro）

**前置条件**：setter 及以上；本地有题包 zip。

**逐步操作**：后台「题目管理」→ 选择 zip →「导入题目包」。三种格式自动识别：

| 格式 | 识别特征 | 会导入的内容 |
|---|---|---|
| 自有（本 OJ 导出） | `meta.txt` | 题面/元数据/testdata/checker.cpp/interactor.cpp（完整往返） |
| DOMjudge | `problem.yaml` + `data/{sample,secret}` | 标题/时限内存/`.in`/`.ans`（嵌套目录平铺重编号）/validator 源码识别为 checker |
| Hydro | `problem.yaml` + `problem_zh.md` + `testdata` | 标题/时限内存/数据/`check/checker.cpp`（识别为 SPJ） |

- 导入的题目一律为「隐藏」，成功后自动跳转编辑器；核对无误再手动改可见性。
- **DOMjudge validator 的参数约定与本 OJ 不同**（本 OJ 是
  `./checker <in> <ans> <out>`，exit 0=AC），导入后必须人工核对 checker 逻辑。
- 只有 `.in` 没有答案的测试点整包忽略（交互题请用自有格式，或导入后单独补传）。

**验证**：提示「已导入 #ID（N 个测试点，格式 X）」→ 编辑器抽查两个测试点
预览 → 提交正确解应 AC。

## 四、我要从外部 OJ 导入题面

**前置条件**：所有登录用户均可导入；目标平台需在插件注册表中（内置题面爬虫：
codeforces、luogu）。入口按角色分两处：

- **管理员 / 出题人**：后台「题目管理」→「外部题面导入」——导入直接进入
  正式题库（免审核）。
- **普通用户**：「个人中心」→「导入外站题目」——导入的题进入审核队列
  （通过前隐藏，管理员通过后公开）。

**逐步操作**（两处相同）：

1. 选择来源，填题号（Codeforces 如 `1900A`、洛谷如 `P1001`），先点「预览」
   核对题面与注意事项，再确认导入。
2. 导入内容 = 题面 + 公开样例（Codeforces 题面含输入 / 输出说明与样例
   代码块，公式可正常渲染；洛谷受平台反爬影响可能暂时失败，稍后重试）。
3. **没有测试数据**：题目带「待补测试数据」标记（判定 = 外部来源 + 0 测试点，
   出现在「我的题目」、审核队列与题目详情页），补齐测试数据前不能用于
   正式评测或比赛。

**验证**：管理员导入后跳转题目编辑器；普通用户导入 → 后台「题目审核」队列
出现带「外部导入 · 待补测试数据」徽章的题目，通过后公开。

## 五、我要导出 / 共享题目（公平性红线）

编辑器「导出 zip」走的是**完整导出**：`statement.md` + `meta.txt` + 全部
`testdata/` + `checker.cpp`/`interactor.cpp`（SPJ/交互题自动带上，导入时还原
判题模式），可在另一套 YSNB OJ 上完整还原。

需要把题目分享给外站/外校时，用**共享导出**：同一导出接口加 `?shared=1`
（`/api/v1/problems/:id/export?shared=1`）。共享包只含题面 + 由公开样例生成
的 testdata，**不含 checker/interactor，也不含隐藏测试数据**。

> 红线：两条通道语义不得混淆。完整测试数据与 checker 永不经过共享通道出站；
> 对外只发 `-shared` 包。checker 编码了判题意图，泄露 checker 等于泄露标程逻辑。

## 六、我要审核用户出题

普通用户在「我的题目」里出的题进入审核队列，通过前为「隐藏」、不可被提交。

**逐步操作**：后台「题目审核」（setter 及以上可见可操作）→ 队列逐题「通过」
或「驳回」。

- 通过：题目进入公开题库（仅注册用户可见），作者收到结果。
- 驳回：作者可修改后重新提交审核。
- 审核要点：题面完整、样例正确、有时限内存、测试数据已上传、来源标注合规。
  带「外部导入 · 待补测试数据」徽章的是普通用户从外部 OJ 导入的题——题面
  与样例已自动带入，**通过前先补齐测试数据**。

**验证**：通过后以普通账号在题库能搜到该题并可提交。

## 七、我要办一场 ACM 比赛（含封榜与滚榜）

**前置条件**：setter 及以上；题目已在题库就绪（挂题会生成比赛内独立副本，
之后改题库原题不影响比赛）。

**逐步操作**：

1. 后台「比赛管理」，填写：名称、说明、开始/结束时间。
2. 赛制选「ACM（罚时 + 首对即停）」。
3. 开关：「启用封榜」（配合「封榜时间」到点自动冻结，留空 = 不自动封榜）、
   「赛时手动封榜」（关掉后裁判台的手动封榜开关将被拒绝）、「需要报名」。
4. 「初始题目」里勾选题库题目，点「创建（ACM 赛制）」。
5. 赛后在同页下方继续管理题目：勾选题库题「复制挂入（独立副本）」，或
   「新建专属题」（隐藏属性、不进公共题库，适合比赛原创题）；「删除」会连同
   测试数据一起删。

**封榜与滚榜**（比赛页「裁判台」，比赛创建者或 admin 可见）：

- 冻结期间选手看到的榜单停在冻结时刻，裁判仍见实时数据。
- 自动封榜按「封榜时间」触发；裁判台「手动封榜」开关可随时冻结/解封。
- 滚榜揭晓：「滚榜揭示控制台」填入数量，按真实最终榜**从最后一名向前**逐队
  解除遮罩，已揭示队伍的真实成绩即刻上榜（配合投屏做颁奖仪式）。

**验证**：开赛前用测试账号报名并提交一题，确认榜单计题数与罚时正确；
冻结后选手视角榜单停更、裁判视角仍实时。

## 八、我要办一场 IOI 比赛（配分值表）

与 ACM 流程相同，差异只有两点：

1. 赛制选「IOI（测试点部分分，按总分排名）」。
2. 赛前为每道题配好 IOI 分值表（见第二节末），建议每题合计 100 分。
   ACM 赛制忽略分值表，IOI 赛制下每个测试点按配分计部分分。

**验证**：提交一份只能过部分测试点的代码，榜单应显示该题部分分而非 0/1。

## 九、赛中裁判操作（比赛页「裁判台」）

裁判 = 比赛创建者或 admin。入口：比赛页 →「裁判台」标签页。

- **公告**：比赛页上部公告卡，输入即「发布」，可随时删除（如
  「B 题数据已更新并重测」）。
- **调整比赛时间**：裁判台「比赛时间」，改开始/结束即生效（倒计时与封榜计划
  跟着走），用于延时/延长。
- **报名管理**：查看报名名单，改类型（正式队伍 / ★ 打星队），或删除报名。
  打星队不占名次，常用于教练队、嘉宾队。组队赛由队长以队为单位报名。
- **用户标记**：搜索并选中选手后勾选「打星（不占名次）」或
  「作弊（出榜标红）」，保存即更新榜单；「已标记用户」列表可一键撤销。
- **重测本题**：「题目」标签页每题的「重测本题」——该题全部有效提交重新
  排队评测（数据修错后用，并配合发公告）。
- **取消/恢复/重判单条提交**：「提交记录」标签页逐行操作；被取消的提交计分
  为零，恢复后可再「重判」。
- **导出榜单 CSV**：比赛页顶部「导出榜单 CSV」。
- **投屏模式**：顶部「投屏模式」在新标签页打开 `/contests/:id/board` 全屏
  榜单，接投影用。

**举例（作弊处置）**：确认某选手抄袭 → 裁判台「用户标记」勾选「作弊」→
保存 → 榜单该行标红出榜；如需彻底抹掉成绩，再到「提交记录」取消其全部提交。

## 十、我要管理用户

入口：后台「用户管理」（admin 及以上）。

- **邀请码**：设置「可用次数」（1–999）与「有效小时」（0–720，0 = 不限）后
  「生成」；列表显示已用/上限与过期时间，可手动删除（已注册用户不受影响）。
- **CSV 批量导入**：格式 `username,student_no,nickname,password`（password 可
  省略，省略则自动生成 10 位随机密码）。导入后逐行显示结果表：用户名 / 初始
  密码 / 错误——坏行与重名行（`username X already exists`）单独标错，不影响
  其他行。**生成密码只显示这一次**，请立即导出分发。单次上限 5000 行。
- **重置密码**：行内「重置密码」，新密码在弹窗显示一次，关闭后不再可见，
  请线下转交。
- **封禁/解封**：行内按钮。admin 只能封禁 user/setter；封禁 admin 需
  super_admin。封禁即时生效。
- **改角色**：行内下拉。admin 只能 user↔setter；super_admin 可授予/收回
  admin 与 super_admin。不能改自己；系统保底一名 super_admin。
- **编辑**：行内「编辑」可改学号、昵称（用户名不可改）。

## 十一、我要看判题机状态 / 排查判题问题

### 判题机监控（后台「判题机监控」，admin 及以上）

- 顶部横幅显示等待判题队列长度；表格列出每台判题机的状态、并发上限、
  正在判题数、最近心跳（心跳超过 60 秒未更新即判 offline）。
- 页面经 WebSocket 实时推送 + 10 秒轮询，刷新无需手点。
- 「数据总览」（admin 及以上）另有 8 项指标卡、近 14 天提交趋势、近 24 小时
  判题并发与判题机负载表，30 秒自动刷新。

### 日志查看器（后台「日志查看器」，admin 及以上）

读取 oj-api 与 oj-judge 两个 systemd unit 的 journald 日志：

- 进程三选：全部进程 / API 服务 / 判题机；关键字过滤（回车生效）；行数
  100/200/500/1000；每 15 秒自动刷新，也可手动「刷新」。
- 级别彩色徽标：error 红 / warn 橙 / info 绿 / debug 灰。
- 服务端以固定参数调用 journalctl（参数不随请求变化，无注入面），取两个
  unit 最近 2000 条记录后在服务端按你的筛选条件保留最后 N 行。
- 前提：运行 oj-api 的系统用户已加入 `systemd-journal` 组（一次性运维操作，
  见 deploy.md）；否则页面报「journalctl 读取失败」。

### 排查示例：某提交判了 SE

1. 拿到提交 ID（提交记录页 URL 里的数字）。
2. 「日志查看器」→ 进程选「判题机」→ 关键字填该提交 ID → 查询。
3. 每个提交判完都有一条 INFO `submission judged`（含状态/耗时/内存）；SE
   会另有 ERROR 行给出具体环节（取数据失败、checker/interactor 异常退出、
  沙箱错误等）。
4. 按原因处置后重判：比赛内提交在「提交记录」点「重判」；题库（非比赛）
   提交由 admin 调 `POST /api/v1/admin/rejudge/:id`。

### 常见判题故障

- 全部提交 PENDING：判题机 offline → 查 `OJ_DAEMON_TOKEN` 是否与 API 端
  `OJ_DAEMON_SECRET` 一致、`systemctl status oj-judge`。
- 队列堆积：临时提高判题机 `OJ_MAX_PARALLEL`（改 env 后 restart），或加一台
  判题机（架构原生支持多判题机）。新判题机先跑 `oj-judge --selftest` 验证沙箱。
- 某语言全 CE：判题机缺编译器，装好工具链后 `systemctl restart oj-judge`。
- 全部 SE：常见于判题机磁盘满或判题工作区不可写。

## 十二、我要给外部工具开 API Key

入口：后台「API 密钥」（admin 及以上）。

1. 填名称（如 `rank-bot`、`dashboard`）→「生成新 Key」。
2. 完整 Key 只显示一次：`ojk_` 前缀 + 32 位十六进制，立即复制保存。
3. 用法：请求头 `X-API-Key: <key>`（或 URL 参数 `?api_key=`）。
4. 列表可查看每把 Key 的前缀、状态、创建时间、最近使用；「吊销」立即失效，
   使用该 Key 的调用马上失败。

说明：公开读接口（`/api/v1/public/...`：用户摘要、题目列表、题目样例、cph
桥接）匿名也可用，Key 用于审计与受保护端点；泄露时在列表页吊销即可。

## 十三、我要看插件清单 / 配 webhook

入口：后台「插件系统」（setter 及以上可看清单；webhook 管理需 admin）。

- 页面列出编译期注册的三类插件：题目爬虫（题库导入用，内置 codeforces、
  luogu）、刷题平台适配器（刷题统计报表用，内置 codeforces、luogu、atcoder、
  nowcoder）、事件钩子（webhook）。
- **Webhook 目标**：判题完成后向目标 URL POST JSON（含
  `id/status/score/problem_id/contest_id/user_id/at`），适合接机器人、排行榜。
  填名称 + URL「添加 / 更新」，按名称「删除」。
- URL 有 SSRF 防护：只允许 http/https，回环地址与内网目标会被拒绝，保存即
  校验，非法 URL 直接报错不落库。

## 十四、备份与恢复（例行）

- `/opt/oj/backup.sh`：每日 03:00 cron 自动备份（PostgreSQL dump + data 目录
  快照），保留 14 天日备 + 6 个月月备；日志在 `/opt/oj/backup/backup.log`。
- `/opt/oj/restore-drill.sh <dump>`：恢复演练（一次性容器或本机临时库，不碰
  生产），每月 1 号 04:00 自动执行，结果在 `/opt/oj/backup/drill.log`。
- 判题机的 blob 缓存是缓存，无需备份；`/opt/oj/data`（testdata 等）才是原始
  资产。
- 手工恢复步骤见 `../operations/deploy.md`。

## 十五、每周检查清单（建议）

| 检查项 | 方法 |
|---|---|
| 服务存活 | `systemctl status oj-api oj-judge nginx` 全部 active |
| 备份 | `backup.log` 里 03:00 的备份成功、dump 体积正常 |
| 恢复演练 | 每月 1 号后看 `drill.log` 末尾是否 `drill PASSED` |
| 磁盘 | `df -h /`（数据目录 + 判题工作区 + 备份），水位 < 80% |
| 判题机 | 后台「判题机监控」：状态 online、队列归零 |
| 日志 | 后台「日志查看器」扫一眼近 200 行有无异常 error |
| 安全更新 | `apt update && apt upgrade`；确认 env 文件权限 600 |

## 十六、故障排查速查

| 现象 | 处置 |
|---|---|
| 提交全 PENDING | 「判题机监控」看在线状态；offline 按第十一节查 token 与服务状态 |
| 某语言全 CE | 判题机缺编译器；装好后 `systemctl restart oj-judge` |
| 某语言全 SE/RE 且空报错 | 沙箱 seccomp 误杀；日志查看器选「判题机」搜 `SIGSYS`，收集后反馈开发 |
| 单题大面积 WA（疑数据错） | 修数据 → 比赛页「重测本题」→ 发公告说明 |
| 榜单不刷新 | 比赛是否封榜；刷新页面重连 WebSocket |
| 日志查看器报错 | oj 用户未加入 `systemd-journal` 组，按 deploy.md 操作后重试 |
| 网页 502 | nginx 与 oj-api 是否存活；nginx `client_max_body_size` 是否 ≥ 160M |
| API Key 突然全部失效 | 检查是否被误吊销（「API 密钥」页状态列），重新生成并线下分发 |
