# YSNB OJ 管理与出题手册

> 适用对象：管理员（admin / super_admin）与出题人（setter 及通过审核的
> 用户出题作者）。部署/判题机等运维内容见 `deploy.md`；接口与架构见
> `architecture.md`。

## 一、角色与权限

| 角色 | 能做什么 |
|---|---|
| user | 刷题、比赛、题单、小组、用户出题（走审核） |
| setter | + 题库直接出题、创建题单、进后台只读页、审核队列可见 |
| admin | + 用户管理（封禁/重置密码/邀请码）、题目审核、判题机监控、重判 |
| super_admin | + 授予/收回 admin、封禁 admin |

- 角色调整：admin 只能改 user↔setter；admin 的授予/收回由 super_admin 在
  「用户管理 → 高级」里操作。系统必须始终保留至少一名超级管理员。
- 封禁即时生效（已登录会话也会被踢出登录态）。

## 二、用户管理（后台 · 用户）

- **邀请码**：生成（可设次数上限），过期/用完自动失效；可手动删除
  （已注册用户不受影响）。批量名单用 CSV 导入。
- **重置密码**：为用户生成临时密码，界面会显示一次，请线下转交。
- **封禁/解封**：封禁后该用户无法登录、无法提交。
- **角色修改**：见上表权限边界。

## 三、出题（后台 · 题库 → 新建题目）

1. 用「新建题目」进入**全页编辑器**：左侧编辑、右侧实时预览（TipTap
   富文本，支持代码块/图片/链接）。
2. 配置时限/内存/可见性/判题模式：
   - **标准比对**：与 `.out` 文件比对（行尾/末空白有容差）。
   - **SPJ 特判**：贴或上传 checker（`./checker <in> <ans> <out>`，
     exit 0=AC，stderr 首行作为反馈展示给选手）。
   - **交互题**：贴或上传 interactor（`./interactor <in>`，与选手程序
     stdin/stdout 直连；exit 0=AC / 1=WA）。
3. 上传测试数据：整包 zip（`<n>.in/<n>.out`）或逐个追加测试点；交互题
   允许没有 `.out`。
4. 可见性：`隐藏`（仅自己）、`仅注册用户`、`公开`。**用户出题**走审核流：
   提交后进审核队列，admin 批准后才对他人可见、才可提交。
5. 导出 zip / 复制题目：导出包含题面 + 元数据 + 测试数据 +
   checker/interactor 源码，可在别处完整还原。

### 题目包导入

题库页「导入题目包」，三种格式自动识别：

| 格式 | 识别特征 | 会导入的内容 |
|---|---|---|
| 自有 | meta.txt | 题面/元数据/testdata/checker（完整往返） |
| DOMjudge | problem.yaml + data/{sample,secret} | 标题/时限内存/数据（嵌套目录平铺重编号）/validator 源码 |
| Hydro | problem.yaml + problem_zh.md + testdata | 标题/时限内存/数据/checker |

注意：DOMjudge validator 的参数约定与本 OJ checker 不同（本 OJ 是
`<in> <ans> <out>`），导入后必须人工核对；导入的题目一律 `hidden`，核对
后手动改可见性。

## 四、比赛编排（后台 · 比赛）

- 创建比赛：ACM 赛制，设置开始/结束时间、**封榜开关**（可整体禁用或仅
  禁用手动封榜）、报名开关、组队赛模式与队伍人数上限。
- 题目：从题库选择（比赛内生成**独立副本**，改题不影响已挂比赛）。
- 赛中裁判（比赛页管理面板）：
  - 公告发布；查看报名名单、修改报名类型（正式/打星）；
  - **打星**（成绩不计排名）与**作弊标记**（保留行但剔除计分）；
  - 取消某次/某人/某题的提交（重判回 正确成绩）；
  - 手动封榜/解封；调整比赛时间；滚榜揭晓（逐步公开被冻结的底部名次）。
- 组队赛：报名以队为单位（仅队长可报名），榜单自动按队聚合。

## 五、判题机监控（后台 · 判题机）

- 显示每台判题机的状态/容量/当前负载/支持语言；队列长度实时可见。
- 判题机掉线：先看 `systemctl status oj-judge` 与日志，再核对
  `OJ_DAEMON_TOKEN` 是否与 API 端 `OJ_DAEMON_SECRET` 一致。
- 队列堆积：临时提高判题机 `OJ_MAX_PARALLEL` 或加一台判题机（架构已支持
  多判题机，gRPC 接入）。
- 全部 SE：通常是判题机磁盘满或 `/oj-work` 不可写。

## 六、备份与恢复

- `/opt/oj/backup.sh`：每日 03:00 cron 自动备份（PostgreSQL + data 目录），
  保留 14 天日备 + 6 个月月备。日志在 `/opt/oj/backup/backup.log`。
- `/opt/oj/restore-drill.sh <dump>`：恢复演练（本机临时库/一次性容器），
  每月 1 号 04:00 自动跑一次，结果在 `/opt/oj/backup/drill.log`。
- 手工恢复步骤见 `deploy.md` 第三节。
- 判题机 `judge-data` 是缓存，无需备份；`/opt/oj/data` 才是原始资产。

## 七、日常检查清单（每周建议）

| 检查项 | 方法 |
|---|---|
| 服务存活 | `systemctl status oj-api oj-judge nginx` |
| 备份日志 | 3:00 的备份是否成功、dump 大小是否正常 |
| 演练日志 | 每月 1 号的 drill 是否 PASS |
| 磁盘 | `df -h /`（判题工作区 + 数据目录 + 备份） |
| 判题机 | 后台判题机页：状态 online、队列归零 |
| 安全 | `apt update && apt upgrade`；确认 env 文件权限 600 |

## 八、故障排查速查

| 现象 | 处置 |
|---|---|
| 提交全 PENDING | 看判题机监控；判题机 offline 则按第五节排查 |
| 某语言全 CE | 判题机缺编译器（如 openjdk-17）；`apt install` 后重启 oj-judge |
| 某语言全 SE/RE（空报错） | 沙箱 seccomp 误杀，看判题机日志 `SIGSYS`，收集后反馈开发 |
| 榜单不刷新 | 比赛是否封榜；WS 是否断开（刷新页面重连） |
| 502 | nginx 与 api 是否存活；`client_max_body_size` 是否 160M+ |
